# Netflix OOP Project + Streaming UI Prototype

A Java console-based Netflix-style streaming service simulation. It demonstrates object-oriented design and service workflows with in-memory data only (no database, streaming API, or real payment processing).

## Requirements
- JDK 8 or newer
- Terminal or an IDE such as IntelliJ IDEA / VS Code

## Launch the streaming UI\n\nOpen [`web/index.html`](web/index.html) directly in a browser for the responsive Netflix-inspired app interface. UI documentation: [`web/README.md`](web/README.md). This is a front-end prototype with mock catalog content; it is not connected to the Java simulation/backend yet.\n\n## Run the console demo
From this directory:

```bash
javac *.java
java NETFLIX_DEMO
```

## Run regression tests
```bash
javac *.java
java NETFLIX_SMOKE_TEST
```

The test runner delegates to feature-focused suites:
- `CatalogSmokeTests` — catalog lifecycle, search, filters, sorting, metadata boundaries
- `PlaybackSmokeTests` — queue recovery, sessions, offline download state
- `BillingSmokeTests` — plans, invoices/refunds, wallet defaults, promo redemption, expiry validation
- `UserFeatureSmokeTests` — review moderation, history/progress, recommendations, playlists, watch parties, health state

GitHub Actions compiles and runs the smoke tests with Java 8 and Java 17.

Remove generated bytecode before committing:

```bash
rm -f *.class
```

PowerShell:
```powershell
Remove-Item *.class
```

## Feature overview
- Catalog lifecycle, search, filtering, ranking, and sorting
- User profiles, favorites, watchlist, history, progress, and preferences
- Subscription plans, trials, coupons, billing records, invoices, and refunds
- Payment-method masking and wallet/default-method management
- Reviews, moderation flags, tags, and helpful votes
- Playlists, bookmarks, playback queues, viewing sessions, and watch parties
- Offline-download simulation, progress, priorities, storage estimates, and failures
- Recommendations and analytics/reporting

## Main classes
| Class | Responsibility |
|---|---|
| `NETFLIX_DEMO` | Feature-focused scripted demonstration |
| `Movies` | Movie entity and compatibility facade |
| `MovieCatalog` | Catalog storage, lifecycle, search, filters, ranking, and sorting |
| `NETFLIX_USER` | Profile and personal viewing state |
| `Subscription`, `SubscriptionPlan` | Subscription and billing lifecycle |
| `PaymentMethod`, `PaymentWallet`, `PromoCode` | Payment simulation |
| `MovieReview` | Review, rating, and moderation state |
| `NetflixPlaylist`, `PlaybackQueue`, `bookmark` | Collections and playback navigation |
| `ViewingSession`, `WatchParty` | Session and group playback state |
| `OfflineDownloadManager` | Download queue and storage accounting |
| `RecommendationEngine` | Personalized recommendation logic |
| Analytics/report classes | Catalog, engagement, accessibility, and system summaries |

## Architecture and migration notes
Catalog operations were extracted to `MovieCatalog`; the static methods on `Movies` remain as compatibility wrappers. The demo was split into feature methods and tests into feature suites. See [ARCHITECTURE_REVIEW.md](ARCHITECTURE_REVIEW.md) for completed hardening, audit notes, and the roadmap.

## Limitations
- State is in-memory and resets when the program exits.
- This is an educational simulation; no media is streamed and no real payment is processed.
- Demo values are placeholders. Never use real passwords, card numbers, or personal information in sample code.
- Arrays and fixed capacities remain in several classes to keep the exercise approachable.
