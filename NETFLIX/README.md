# Netflix OOP Console Demo

A Java console-based Netflix-style streaming service simulation. It demonstrates object-oriented programming and several service workflows using in-memory data (no database or external API).

## Requirements
- JDK 8 or newer
- A terminal, or an IDE such as IntelliJ IDEA / VS Code

## Run
From this directory:

```bash
javac *.java
java NETFLIX_DEMO
```

Run regression smoke tests:

```bash
javac *.java
java NETFLIX_SMOKE_TEST
```

GitHub Actions also compiles and runs these tests with Java 8 and 17.

To remove generated bytecode before committing:

```bash
rm -f *.class
```

Windows PowerShell equivalent:

```powershell
Remove-Item *.class
```

## Features demonstrated
- Movie catalog, filtering, sorting, trending, and search
- User profiles, favorites, watchlist, watch history, progress, and settings
- Subscription tiers, trials, coupons, billing records, invoices, and refunds
- Payment method masking and wallet/default-method management
- Reviews, moderation flags, tags, and helpful votes
- Playlists, bookmarks, playback queues, viewing sessions, and watch parties
- Offline download simulation, progress, priorities, storage estimation, and failure/retry
- Recommendations and catalog, engagement, accessibility, audit, and system-health summaries

## Main classes
| Class | Responsibility |
|---|---|
| `NETFLIX_DEMO` | Runs a demonstration of the system |
| `Movies` | Movie model and static catalog operations |
| `NETFLIX_USER` | User profile and personal viewing data |
| `Subscription`, `SubscriptionPlan` | Plan and subscription lifecycle |
| `PaymentMethod`, `PaymentWallet`, `PromoCode` | Payment-related simulation |
| `MovieReview` | Reviews, ratings, tags, and moderation |
| `NetflixPlaylist`, `PlaybackQueue`, `bookmark` | Personal collections and playback |
| `ViewingSession`, `WatchParty` | Playback session and group viewing |
| `OfflineDownloadManager` | Simulated downloads and storage |
| `RecommendationEngine` | Personalized recommendation logic |
| Analytics/report classes | Catalog, usage, accessibility, and system summaries |

## Notes / limitations
- All state is stored in memory and resets when the program exits.
- This is an educational simulation; it does not stream media or process real payments.
- The demo uses placeholder data only. Never use real passwords, card numbers, or personal information in sample code.
- The project currently uses arrays and fixed capacities in several classes to keep the OOP exercise approachable.
